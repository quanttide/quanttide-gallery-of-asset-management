# 根第二大脑

## 契约

### 目标

根第二大脑（`quanttide/quanttide`）是量潮第二大脑的根仓与入口，用四条正交的轴组织全部资产：范畴轴 `categories/`（我如何运行）、领域轴 `domains/`（我关心什么）、主体轴 `defaults/`（我是谁）、适配轴 `adapters/`（我如何被接通）。各轴资产独立成仓，根仓只追踪引用，不直接改子仓文件。

### 主体与领域

`defaults/` 与 `domains/` 不是平行同级，而是先后两级：

- `defaults/` 收组织主体自己的信息，是默认入口。公司、实训基地、联盟、创始人各成一个仓库，格式由主体自己定。
- `domains/` 为方便构建平台而设：按平台组织信息的方式，把某一块信息切出来统一组织。例如组织档案在 `domains/` 里统一收公司、联盟、基地的组织管理信息。

最严谨的走法：先进入对应的 `defaults/` 主体，再分流到 `domains/` 领域。跳过主体直接进领域，主体档案一旦格式过时就会卡住下游——例如 profile 格式旧了，流转流程随之受阻。

### 设计意图

这是刻意设计的两级结构，不是历史遗留：

1. 先汇总开源，再规范形式——先把各组织的原始信息汇总公开，到领域层再整理形式、统一规范。反过来先定统一格式，信息就不容易被充分披露。
2. 多主体即多验证——公司、实训基地、联盟作为不同组织，信息天然不同；保留差异等于给产品提供多组真实样本，用来验证领域层的规范是否成立。

### 流水线

排期先行：先定发布顺序，再把工作按主体 → 领域的路径分派出去，便于流水线作业交给不同的人（例如人事云可以排在元工程之前）。

### 验收

- 四轴目录齐备，与[产物类别](../category/second-brain.md)对得上。
- `defaults/` 下主体各成独立仓库，未接入的主体不预留空目录。
- 新信息先落主体、再按领域分流；两处归属不清先报告，不硬塞。
- 领域规范变更时回看主体档案是否仍成立；主体档案格式变更时检查下游流程是否受阻。

## 结构

```text
quanttide/
├── categories/   范畴轴：标准范畴的聚合容器（12 个）
├── domains/      领域轴：51 个领域仓库，各为领域第二大脑
├── defaults/     主体轴：公司、实训基地、联盟、创始人
├── adapters/     适配轴：飞书、GitHub、Hermes、Pi
└── .quanttide/   元数据与契约
```

## 目录

- 主体（`defaults/`）：公司 `quanttide-tech`、实训基地 `quanttide-academy`、联盟 `quanttide-alliance`、创始人 `quanttide-founder`
- 领域（`domains/`）：51 个领域仓库，完整列表见根仓 `domains/README.md`
